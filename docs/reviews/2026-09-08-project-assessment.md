# Retrue 整体评估与问题清单

评估日期：2026-09-08。代码基线：`7d4c369`。配套：[后续 AI 执行计划](../plans/2026-09-08-project-remediation-plan.md)。

## 1. 结论

**现有方向可以采用，但需要先补数据正确性、安全边界和日常工作闭环，再扩大使用范围。**

项目已经超过概念原型：客户、首评/复评、课程计划、排课、训练记录、课时包、AI 草稿确认和客户知识都有实现。Django + Vue 单体、业务服务控制正式写入、AI 草稿人工确认的方向合理。主要问题不是模块数量不足，而是同一业务经过不同入口时，校验、字段、审计和恢复规则不一致。

本次只评估、局部验证并编写计划，不修改业务实现、不运行生产迁移、不清理业务数据、不提交 Git。检查覆盖主要业务代码、路由、模型、序列化器、前端关键页面、测试配置与通用部署配置；不代表逐行安全审计或线上验收。

### 已有能力，后续应保留

- 课程主链已接通：`RehabPlan → RehabPlanCourse → CourseSession → TrainingRecord`。正式记录确认后完成排课、幂等扣课；不能再列为“没有课程管理”。
- AI 已有客户目录、受控 Tool、领域草稿、康复师确认、任务事件和恢复基础，不能说“完全没有安全边界”。
- 评估有草稿/完成态、指标定义与身份一致的比较规则，正式事实消费已考虑完成态。
- 前端已有独立手机视图和适配路由；后端有测试，前端有 SSE 测试。
- 已有审计、行锁、唯一约束和生产配置检查；需要补齐遗漏入口，不是推倒重做。

### 证据等级与优先级

“局部复现”表示本次执行实际代码得到反例，隔离条件见第 6 节；“代码确认”表示代码直接支持但未完整 E2E；“待验证风险”需要并发、浏览器或部署环境确认；“设计待定”不能由后续 AI 擅自决定。

P0：扩大真实使用前应解决的权限/事实正确性问题；P1：稳定试用必需；P2：效率与维护性。优先级是工程判断，不是外部认证。

## 3. 数据、安全与状态问题

### F01 / F02：修改接口的归属漏洞

- `retrue-server/apps/training/views.py:82`：修订先验证旧记录归属，然后复用可写 `customer` 的创建序列化器，未调用 `_get_own_customer`；没有排课时 `_validate_course_session` 直接返回。
- `retrue-server/apps/training/home_views.py:41`：修改只检查旧计划归属，随后直接保存可写客户字段。

反例：甲修改自己的记录/家庭训练，提交乙客户的引用，HTTP 200 且保存交叉关联，响应可带出乙客户姓名。准确影响是“把甲的记录挂到乙的客户”，不是已经证明“可以修改乙的所有记录”。

建议创建后客户默认不可更换；错绑纠正另设受控动作。关联 queryset 按当前康复师收窄，领域服务再次验证。同查 PUT/PATCH/草稿确认入口。已有异常数据只做只读报告，不自动迁移。

### F03：训练项目语义丢失

`training/models.py` 已有 `activity_type/quantity/unit`，批量草稿也携带这些字段，但 `training/serializers.py:15` 没包含它们；`ai/services/training_parser.py:840` 创建正式动作时也未写入。手动修订整体删除并重建动作，可能进一步重置已有字段。

实测输入按摩类型、数量 1、单位“次”，序列化通过后只剩名称。草稿正确不等于正式保存正确。

建议统一项目契约，贯通单客户、批量、手动、AI 确认、历史修订、时间线、审计；验收重新 GET 正式记录。历史丢失数据不能猜测补回。

### F04：风险判断与解释不一致

`ai/services/risk.py:18` 从最近三条反馈正则提取 NRS，只检查最高值 ≥ 6 且至少两个评分，就写“连续未明显改善”。没有实际判断改善方向、连续性、范围、测量场景；重复检测也没有来源去重。

实测旧值 8、新值 1 仍触发同样描述。缺失评分的记录被跳过也不能据此声称连续。

建议先移除无证据结论，展示实际记录与待核查状态；专业规则需有版本、输入条件和边界测试。**本评估不制定新医学阈值**；触发规则与建议动作需专业负责人确认，AI 不改变课程或处理结果。

### F05：认证边界

`accounts/views.py:26` 登录为 `AllowAny`、`authentication_classes=[]`，未单独做 CSRF 校验；本地安装的 DRF `APIView.as_view()` 标记 `csrf_exempt`。已认证 Session 请求的 CSRF 保护不能代替登录保护。

已查 accounts/config 与通用代理配置未见登录限流；账号创建/重置只做长度约束并 `set_password`，未调用 `validate_password`。不据此认定已经遭攻击或宿主机没有额外防护。

建议补 CSRF 初始化与登录验证、账号/IP 限流、统一密码验证；避免永久锁号引入恶意锁定问题。

### F06 / F07：并发、日期与完成态

`schedules/services.py:121` 以查询判断重叠，同一计划课程有锁，不同计划课程/无计划课程缺共同互斥点；架构文档也承认此窗口。`schedules/views.py` 在锁外判断 `has_formal_record`，而 `update_course_session` 加锁后未完整重跑保护。

可能失败：取消请求先看到未完成，训练确认随后完成并扣课，取消请求拿锁后覆盖刚完成状态；两个不同课程同时通过冲突查询。需 PostgreSQL 双连接并发复现。

代码还允许已完成排课改日期，训练修订的日期检查又对当前关联记录放行，可形成日期不一致。

建议统一锁顺序和康复师维度排课互斥，将不变量放入锁内领域服务复核；已完成日期修改拒绝或走同步纠正流程。保留无物理外键约定，不默认引入分布式锁。

### F08：修订、审计、错误

训练修订的对象与 before 快照在事务外读取，缺版本号/更新时间冲突检查；两个编辑页面可静默覆盖。`customers/services.py:82` 的更新与审计不在同一事务；家庭训练父子写入无原子性/审计，回访修改也未写审计。

实测训练列表 `customer_id=abc` 返回 500，应是可解释的参数错误。建议按高价值写入逐项补冲突响应、事务与审计，排查同类参数转换；不要求所有读取都加锁。

## 4. AI 与功能闭环

### F09 / F10：入口与恢复不统一

`conversations/views.py → send_user_message` 直接调用 provider；`knowledge/views.py → rag_answer` 走独立 RAG；`ai/services/preparation.py` 直接调用 `provider.prepare_lesson`。它们未统一经编排，和 AGENT.md 第 15 条不一致。旧会话在同一 HTTP 请求里顺序刷新摘要、评估记忆，异常不回滚不等于耗时不阻塞。

`assistant_tasks/streaming.py` 已有每进程 4 个 slot、180 秒流上限和断开提示，但 daemon 工作线程会继续。`assistant_tasks/services.py:629` 根据 `AI_TIMEOUT+30` 和活动时间恢复任务；时间到/流断开不证明旧执行已退出。是否出现迟到结果覆盖、重复草稿，需故障注入验证，不能直接认定已发生。

建议先列页面/API/服务/图/正式确认入口矩阵，旧入口兼容转发到现有图，内部模型子调用也由节点管理。增加执行 attempt 所属权和旧结果拒收规则；不强杀线程、不自动重发业务请求。是否引入持久队列，依据重启恢复要求和容量证据决定。

### F11：检索正确性

`knowledge/services.py:112` 先取相似度 top-k 再排 high，`:135` 先取最新 top-k 再排 high，旧但重要的安全限制可能根本不在候选中。无向量兜底没有匹配问题文本，只是最近条目列表。

`KnowledgeItemDetailView.put` 修改内容不清 embedding；`build_knowledge_index` 只处理空 embedding，“重建”不会更新这些旧向量。旧 RAG 只筛 `is_active`，与长期记忆的 `status=active`、有效期语义不一致；不能据此说当前数据已全部冲突。

建议安全限制独立召回，再追加相关片段；统一生命周期过滤；embedding 绑定内容版本，修改后失效，重建限量且可追踪。事实查询、长期记忆与自由文本 RAG 分别处理，不把所有事实向量化。

### F12 / F13：一天的工作尚未收口

PC/手机首页主要读取今日课程；手机只展示前 5 节并有课表入口，不能说其余课程完全不可见。产品第 18 节承诺的今日回访、待复评未接入，跨日未回填也未形成统一待办。

`AuxiliaryServices.vue:135` 完成回访固定保存 `result: '已完成'`，没有真实结果输入，后端也缺对应操作审计。

建议首页整合今日课程、逾期未回填、回访/复评、待确认草稿；每项有主动作和明确完成条件。完成回访录入结果，跳过说明原因；需要后续处理时显式创建下一项，不由 AI 自动决定复评周期。暂不引入复杂通知系统。

### F14：模型存在但操作与交付欠缺

- 家庭训练已有创建/列表，但当前辅助组件缺编辑入口和客户版完整复制交付；列表只拼动作名。产品第 14 节的一键复制未兑现。
- 动作库后端支持官方/个人动作，当前前端路由缺独立管理页面与稳定的动作选择复用入口。
- `CustomerAlias` 与目录匹配已存在，客户 API 路由缺别称维护能力。

建议先补家庭训练编辑/复制、个人动作维护、客户详情内别称维护。图片/视频、客户端本来就是后续范围，不作为 V1 必须缺陷；不默认生成公开分享链接或自动发送消息。

### F15：切换客户的状态风险

`CustomerDetailView.vue:20` 将路由参数保存为常量，只在 onMounted 加载；布局 router-view 未按客户 keyed。`AuxiliaryServices` 也不监听客户属性变化。路由复用时可能 URL 已变而内容/提交上下文仍属旧客户；本次未浏览器复现具体路径。

建议业务身份变化时清理旧状态、重新加载、拒绝迟到响应，保护未提交编辑。验收 A→B 快切且 A 最晚返回，查看内容与保存目标均为 B。

### F16：数据导出、删除与保留

产品第 30 节要求客户导出/删除，目前客户路由只有列表/详情；对话也缺完整可操作的保留/清理入口。知识软删除已存在，但不等于客户所有数据删除。

先设计正式记录、评估、课表、课时流水、草稿、会话、摘要、记忆、向量、审计、备份的处理清单。区分结案、停用、软删、脱敏、清除，确定授权角色和保留期限；先实现只读导出与删除影响预览。未确认规则前不清理。

### F21：需要先定规则的两个取舍

1. 当前余额不足会在 `complete_session_for_record` 整体回滚，这是已有约定，不是新程序错误。但上过课却没余额时，真实训练记录也不能保存。可保留规则并给人工处理入口；若要允许欠费/待核销，须先设计独立状态，不能默默跳扣费。
2. 已确认记录错绑客户/排课需要纠正流程。禁止任意改绑是正确保护；应先设计作废/冲正/新记录及审计，说明课时回补和课程恢复原子性，不能直接放开关联字段。

## 5. 工程与交付

### F17：可运行不等于可恢复

`config/urls.py:22` 健康检查固定返回成功，不访问数据库。生产已有密钥/域名验证、非 root 容器、HTTPS/Cookie 配置；但本次无法证明备份可恢复、迁移失败可回滚或真实 Nginx/ASGI 的 SSE 按时输出。

建议独立 readiness，用短超时检查数据库与必要 schema；外部模型短暂故障不应让整个业务站点死亡。提供不含真实主机信息的备份、恢复、发布/回滚手册并隔离演练。保留宿主机 PostgreSQL/Nginx、Docker 仅后端的拓扑。

### F18 / F22：测试与质量门槛

仓库未见 `.github` CI；后端 requirements 为范围、无锁文件。前端有 package-lock 和 SSE 测试，scripts 只有 dev/build/preview，缺统一测试入口和业务 E2E。已有后端测试不应被忽略，但覆盖应包含跨客户、丢事实、重复扣课等异常。

`ai/orchestration/metrics.py` 已有脱敏计数日志和调用上限；尚缺持续统计真实意图/身份正确率、草稿保真度、延迟、超时、tokens/成本与人工修改量的发布门槛。Mock 通过不证明真实模型可靠。

建议固定依赖和独立测试库，后端串行，关键前端 E2E；真实模型用合成/经允许去标识化样本、固定版本集、费用上限，不先建设大型数据平台。

### F19：先测量，再优化

会话列表最近 50 个会话用带 messages 的 `ConversationSerializer`，会包含完整消息且列表未预取；详情同样不分页。训练时间线一次返回全部记录/动作。`CourseSessionSerializer.get_training_record_id` 使用 `order_by().first()`，无法直接复用普通预取缓存，存在逐课程查询。

前端构建有大 chunk 警告，但路由已经懒加载，不能说全部页面未拆分。先用合成数据测响应大小、SQL 数和 p95，再分页、聚合、预取和必要拆包，不默认上缓存/微服务。

### F20：当前事实和维护边界

- 架构文档称编排默认关闭，`settings.py:134` 默认 true。
- 测试规范仍写 `docker compose up -d postgres`，与现行部署不同。
- 产品第 31 节仍写全部组件进 Docker，与 README 现行拓扑不同。
- 总执行计划混合历史完成/未实现/已替代方案，缺当前功能索引；保留历史，不继续以历史日志代替当前状态。
- 当前 nodes.py 1387 行、AssistantView.vue 1255 行、任务 services 1056 行、编排 service 882 行。行数是信号，问题在身份、查询、卡片和恢复等职责耦合。

建议先补行为回归，再按职责小步抽取；不改公开接口，不为命名重做模型。

## 7. 建议推进次序

先修归属/字段/风险与安全知识，再补认证、事务和 AI 恢复；随后补首页待办、回访结果与家庭训练交付，再完成治理、恢复演练和持续质量门槛。代码拆分和性能优化依据证据小步做。

不建议现在微服务化、增加多 Agent 自治、全面事件溯源或先建设大型 RAG 平台。它们不能直接修复以上已确认问题。详细依赖、验收和后续 AI 启动指令见配套执行计划。
