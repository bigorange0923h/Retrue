# 课程核销与错绑纠正设计

状态：`design_pending`。本文仅提出可审阅流程；未经业务确认不实施新状态、数据表、接口或自动修复历史数据。

## D1 余额不足

事实：当前正式训练记录、完成课程及扣课在同一事务中提交。余额不足整体回滚，草稿仍待确认。本次并发修复保留这一规则。

建议先保留现行行为。允许“训练已发生，但权益待核销”会引入独立的财务状态和补核销责任；仅凭记录已发生不能推定康复师同意赊课，也不能令负余额成为默认行为。

如业务确实需要，建议候选流程：康复师确认“保存训练，待核销”→完整保存正式训练事实→课程展示“待核销”→在未核销列表选择当前客户课时包并检查余额→原子新增核销流水→变为已核销。重试只能复用同一次核销；作废待核销记录不产生退款；已核销记录作废必须走冲正流程。

原型文案：余额不足弹窗显示“当前余额 / 本次需扣 / 差额”；默认操作为“返回草稿”；拟新增的“保存并进入待核销”必须说明记录和权益分别生效，并由康复师明确选择。待核销页显示客户、排课日期、需核销量、创建时间和操作人，不自动选择课时包。

需要确认：是否允许赊课、谁负责处理待核销、是否允许后补课时包、欠核销是否阻止新预约、如何导出及对账。验收反例至少包括同时核销最后一课时、重复点击、补核销与作废竞争，以及核销时课时包发生变更。

## D2 错绑纠正

事实：已关联正式训练记录的排课不能直接更换客户、计划、课时和完成状态；已扣课后不能更换计划课程的课时包。本次继续拒绝改绑，不覆盖旧记录或流水。

建议采用“保留原记录 → 作废及冲正 → 重建正确记录”，避免直接改客户造成健康事实和账务归属悄悄迁移。康复师必须提供纠正理由，界面预览旧客户/排课/消费流水与新客户/排课/拟扣课；确认后在同一事务内复核归属、目标课时余额及目标排课唯一记录约束，再按受控规则执行。

原型流程：原记录详情“申请纠正”→输入理由并选择正确客户/排课→预览原记录保留、原课时退款和新课时扣减→康复师确认→返回原记录与替代记录的双向追溯链接。重复确认使用幂等键；任一步失败全部回滚。原排课恢复为待上课还是保留为作废，需要业务明确决定，不能自动猜测。

需要确认：是否支持跨客户纠正、训练事实如何复制且如何审核、原排课恢复/作废策略、可纠正时间范围、退款课时包已停用时的处理，以及是否需要第二人审批。验收反例包括目标排课已确认、退款与人工调整竞争、新包余额不足、旧记录再次被纠正，以及网络重试。

两项设计未确认前，现有接口只提供明确失败和可重试的并发保护；不得据此生成历史核销或冲正数据。
