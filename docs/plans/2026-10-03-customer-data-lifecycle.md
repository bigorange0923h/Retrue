# 客户资料交付与生命周期设计

本次交付客户级 JSON/中文文本报告导出，以及只读删除影响预览。保留与删除执行依赖整改计划 D3；本文件中后续生命周期规则是待审阅设计，当前没有删除执行接口，也没有按期限自动清除。

## 已实现的资料边界

所有资源先校验当前康复师和目标客户。正式资料直接按 `therapist + customer` 查询；明细通过父表归属链查询，避免因无物理外键而把他人关联记录交付出去。

| 资料 | 明确归属链 | 本次导出 | 删除预览 |
| --- | --- | --- | --- |
| 客户档案/别称 | 客户 + 康复师 | 是，手机号脱敏 | 是 |
| 评估/指标 | 客户评估 → 指标 | 是 | 是 |
| 计划/阶段/计划课程/次数调整 | 客户计划 → 相关子项 | 是 | 是 |
| 排课/课时包/扣退流水 | 客户排课；客户课时包 → 流水 | 是 | 是 |
| 训练/动作；家庭训练/动作 | 客户记录或计划 → 动作 | 是，完整剂量和注意事项 | 是 |
| 回访/复查、风险提示 | 客户 + 康复师 | 是，含结果/跳过原因 | 是 |
| 已存客户长期记忆 | 客户 + 康复师 | 是，保留生效与人工确认标记，不含向量 | 是，向量列随资源计数 |
| 记忆候选/讨论事件 | 客户 + 康复师 | 否，含待审派生内容 | 是 |
| 绑定会话/消息/滚动摘要 | 客户绑定会话 → 消息 | 否，原文可能提及其他客户 | 是 |
| AI 草稿/助手任务及执行子项 | 明确客户 + 康复师 → 子项 | 否，执行状态可能含多客户信息 | 是 |
| 批量训练子项 | 本账号任务 + 明确客户 | 否 | 是 |
| 审计 | 上述资源类型 + 对象 ID + 本账号 actor | 仅导出访问元数据写日志 | 是，原日志继续保留 |

未绑定客户的通用会话、共享批量任务、checkpoint、外部日志、已下载文件和备份不按文本姓名自动认领。预览明确列出这些边界，不能据数据库计数推断它们已经处理。

导出默认移除完整手机号字段，递归脱敏自由文本中的手机号，不包含密钥、向量、AI 原始输入或执行状态。完整联系信息导出没有开放；需要单独确定角色和授权依据。资料超过一万条时明确失败，不静默截断。

下载响应为统一信封里的文件名、内容类型和内容。导出访问审计仅记录格式、脱敏标记、记录数量、操作人、时间及目标客户，不复制整份健康资料。下载后文件的使用和销毁由持有者负责，系统不能撤回已经下载的副本。

## 待确认的生命周期方案

建议采用“结案保留 → 明确授权归档/停用 → 恢复期 → 审阅后清除”的显式流程；`Customer.status=closed` 目前仅表示业务结案，不代表已删除或退出所有 AI 检索。

实施前必须明确：授权角色、正式训练/评估/课时流水保留期限、恢复期、审计最小保留字段与期限、备份过期周期、客户请求的验证方式、共享会话与多客户任务的人工审核方式。现有产品文档没有给出具体年限，因此本次不编造保留期限。

删除执行不能直接调用 ORM `customer.delete()`。建议后续由独立生命周期服务生成计划并审核，停止未完成任务后，在同一业务状态下让客户目录、详情、列表、AI 读取工具、向量检索和后台任务全部遵循生命周期过滤。必须同步处理长期记忆向量、候选、事件摘要、会话摘要、AI 草稿、助手状态与外部检查点，避免删去正式资料后派生内容仍可被检索。

清除先进行只读影响预览，再按实际权限与保留要求作出决定。恢复期内应保存完整归属链，不以新客户记录替代原对象；清除时保留最小授权凭据和执行结果，审计快照是否脱敏由确认的策略决定。备份不能逐行删除时，应有明确失效日期和恢复后再次应用生命周期清单的机制。

## 验收与回退

自动回归覆盖两个账号隔离、结构化资料核对、手机号脱敏、导出审计、重复预览无副作用以及删除方法未开放。真实数据导出、备份恢复演练、删除策略批准与真正清除另行验收。

新增 `CustomerAlias.is_active` 默认 `true`，历史匹配不变；新增审计 `export` 选择值不覆盖历史记录。若回退功能，关闭新增入口即可；不要删除已有别称或导出审计。迁移回退会移除别称启用标记，因此应先确保不再需要保留停用状态。
