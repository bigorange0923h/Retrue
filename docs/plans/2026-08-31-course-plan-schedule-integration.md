# Retrue 课程计划与课表联动执行方案

> 状态：实施中  
> 编写日期：2026-08-31  
> 目标用户：康复师  
> 核心原则：页面使用“安排课程、已安排、待安排、下次上课”等业务语言，不向康复师暴露模型名、ID、批处理规则等技术概念。

## 1. 改造目标

建立以下闭环：

```text
创建客户课程计划
  → 选择“现在安排”或“稍后再说”
  → 康复师确认上课频率、星期和时间
  → 预览即将加入课表的课程
  → 确认后写入课表
  → 完成训练记录
  → 自动更新已上次数、剩余次数和课时
```

课程计划负责“需要上什么、上多少次”，课程表负责“具体哪天几点上”。创建计划不能静默占用康复师时间；所有课表写入必须经过康复师确认。

## 2. 康复师端体验

### 2.1 创建计划后的提示

计划保存成功后显示：

> 课程计划已保存，是否现在安排上课时间？

操作：

- `现在安排`
- `稍后再说`

不得展示“生成 CourseSession”“关联计划课程”等技术文案。

### 2.2 课程计划进度

每一门计划课程展示：

- 计划次数
- 已上次数
- 已安排次数
- 待安排次数
- 下次上课
- 状态

计算规则：

- 已上次数：存在正式训练记录且排课为已完成。
- 已安排次数：状态为待上课的有效排课。
- 待安排次数：`计划次数 - 已上次数 - 已安排次数`，最小为 0。
- 已取消、请假不计入已安排或已上。
- 过去但仍为待上课的课程标记为“待处理”，仍计入已安排，避免重复排课。

### 2.3 安排课程向导

默认只询问：

1. 安排哪一类课程。
2. 从哪天开始。
3. 每周上几次。
4. 通常星期几。
5. 通常几点开始。

系统自动带出客户、课程时长、单次课时和待安排次数。生成结果必须先显示日期、时间和课程名称预览，再由康复师点击“确认加入课表”。

时间冲突使用自然语言：

> 9月8日 14:00 已有其他客户课程，请调整时间。

高级设置收进“更多设置”，不占用主流程。

### 2.4 单次排课

- 从客户课程计划点击“安排课程”时，自动带入客户和该门课程。
- 从课表点击“新增课程”时，选择客户后展示其进行中的计划课程。
- 客户存在进行中课程计划时，普通康复训练必须选择计划中的课程。
- 首次评估、阶段复评和其他事项允许不占用计划次数，但需要选择明确的安排类型。

### 2.5 移动端

- 保留按天查看。
- 增加明显的“安排课程”入口。
- 使用与桌面端相同的简化向导，字段单列全宽。
- 不在移动端展示密集月历或技术统计。

## 3. 后端任务

### 3.1 计划进度统计

计划课程接口增加：

- `scheduled_count`
- `unscheduled_count`
- `overdue_count`
- `next_session`

查询时预取排课，避免逐行重复查询。

### 3.2 排课数量约束

- 新增或改绑计划课程时，锁定对应计划课程。
- `已完成 + 待上课` 不得超过计划次数。
- 已取消、请假不占用计划次数。
- 调减计划次数时，不得小于 `已完成 + 待上课`；康复师需先处理多出的未来课程。
- 关闭计划、暂停或取消计划课程前，若仍有待上课课程，应阻止并返回可理解的处理提示。

### 3.3 安排类型

为排课增加面向业务的安排类型：

- 计划课程
- 首次评估
- 阶段复评
- 其他事项

历史数据按是否已关联计划课程迁移为“计划课程”或“其他事项”。服务端校验安排类型与计划课程是否匹配。

### 3.4 批量安排

增加预览与确认能力：

- 预览不写数据库。
- 根据开始日期、星期、开始时间、课程时长和待安排次数生成候选课程。
- 检查同一康复师时间冲突。
- 确认时重新检查冲突和剩余次数，防止预览后数据变化。
- 批量创建必须处于事务中，不能只创建一半。
- 返回创建数量、课程列表和冲突日期。

### 3.5 既有完成闭环

保留现有规则：正式训练记录保存后，排课变为已完成，课时包幂等扣减，计划课程达到计划次数后自动完成。

## 4. 前端任务

### 4.1 客户课程计划

- 创建成功后询问“现在安排 / 稍后再说”。
- 每门课程增加“安排课程”。
- 增加已安排、待安排和下次上课显示。
- 待安排为 0 时禁用继续安排并提示“该课程已全部安排”。

### 4.2 PC 课表

- 支持从路由参数自动带入客户和计划课程。
- 新增简化批量安排向导和确认预览。
- 单次新增时将“计划内课程”改为“本次安排”，使用业务文案。
- 冲突、超出计划次数、计划已暂停等错误使用可执行的中文提示。

### 4.3 移动端课表

- 增加安排按钮。
- 复用同一安排向导与校验规则。
- 表单保持单列全宽，主要按钮占满整行。

## 5. 测试任务

后端至少覆盖：

- 计划课程统计已上、已安排、待安排、逾期和下次课程。
- 单次排课不会超过计划次数。
- 取消、请假后可以重新安排。
- 调减次数不能小于已上加已安排。
- 计划关闭、课程暂停或取消时处理未来排课。
- 批量预览不落库。
- 批量确认全部成功或全部回滚。
- 预览后产生时间冲突时确认失败。
- 其他康复师不能使用客户或计划课程。
- 历史计划外课程仍可读取。

前端至少验证：

- 保存计划后的两个选择清晰可用。
- 从计划进入排课自动带入客户和课程。
- 计划进度数字与课表一致。
- 桌面端和移动端均可完成安排。
- 375px 宽度无横向溢出。
- 页面没有“计划课程 ID、批量任务、数据库”等技术文案。

## 7. 本轮不做

- 不由 AI 直接写入课表。
- 不自动决定客户可用时间。
- 不处理场地、设备和多个康复师之间的资源调度。
- 不接入外部 Excel 或第三方日历。
- 不静默修改已经确认的历史排课。

AI 后续可以建议课程频率和间隔，但所有日期与时间必须由康复师预览并确认。

## 8. 验收标准

1. 课程计划创建后可以自然进入安排流程，也可以稍后处理。
2. 康复师无需理解系统数据结构即可完成单次或批量安排。
3. 课程计划可直接看到计划、已上、已安排、待安排和下次课程。
4. 课表中的普通康复课程能够可靠归入客户课程计划。
5. 系统不能排出超过计划次数的有效课程。
6. 时间冲突在确认前展示，并使用自然语言说明。
7. 正式训练记录仍能正确完成排课、扣减课时并推进计划进度。
8. 后端测试、前端生产构建和桌面/移动端交互验收全部通过。
