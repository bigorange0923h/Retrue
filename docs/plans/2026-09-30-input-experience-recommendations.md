# Retrue 录入体验优化建议

> 日期：2026-09-30\
> 状态：用户已授权实施；P0/P1 核心流程已接入，真实交互与试用验收待完成；P2 按试用效果决定；现有完成条件保持不变。\
> 范围：首次评估优先，兼顾复评、课后记录、排课与随访。\
> 结论：可以采用，但应先减少重复录入和无效操作，再逐步接入自然语言整理与缺项补充。

## 1. 判断依据与需要验证的假设

用户反馈是“首次评估需要专门填表单，使用稍显麻烦”。这说明存在体验问题，但尚不能判断主要成本来自打字、字段理解、页面切换、网络等待，还是评估本身需要采集的信息。当前没有操作耗时、完成率或访谈统计，下面的收益判断均为设计假设。

2026-09-30 核对当前代码后，可以确认：

| 当前实现事实 | 对体验的可能影响 |
| --- | --- |
| 评估编辑器已有五步引导，点击下一步会保存草稿并在成功后推进 | 已有恢复基础；固定走完步骤和逐步等待保存仍可能增加操作成本 |
| “本次问题”和“主观情况”都展示并编辑同一个 `chief_complaint` | 没有重复保存两份主诉，但用户可能以为需要再次填写 |
| 主观情况同时展开病史、手术史、用药、运动、工作、睡眠等输入框；病史提示本身也包含手术和用药 | 存在信息重叠与较高的视觉负担；是否实际重复填写需观察 |
| 现有 AI 评估 schema 只覆盖日期、主诉、病史、目标、当前状态和备注；不含完整开始时间、因素和客观指标 | 目前自然语言整理不能替代完整评估录入 |
| 领域草稿卡片显示字段代码和值，提供确认/取消，没有字段编辑控件 | 康复师难以在同一处修正结果；摘要文案需要业务化 |
| AI 评估候选确认后创建的是 `Assessment(status=draft)`，不是已完成评估 | 必须区分“内容已存为草稿”与“评估已完成”，避免确认后又填表的落差 |
| 复评已有导入上次已完成评估的项目结构，结果值会清空 | 这项能力应优化入口与复核方式，不应当作全新功能重建 |

代码依据：[评估编辑器](../../retrue-web/src/views/assessment/AssessmentEditView.vue)、[本次问题](../../retrue-web/src/components/assessment/AssessmentProblemStep.vue)、[主观情况](../../retrue-web/src/components/assessment/AssessmentSubjectiveStep.vue)、[领域草稿卡片](../../retrue-web/src/components/assistant/DomainDraftCard.vue)、[评估候选 schema](../../retrue-server/apps/ai/schemas/domain.py)、[领域候选确认服务](../../retrue-server/apps/ai/services/domain_drafts.py)、[评估完成校验](../../retrue-server/apps/assessments/services.py)。本次为源码核对，没有进行浏览器实测。

**核心设计假设：** 康复师愿意先描述实际询问和观察，再检查系统整理的结果。如果整理后仍需逐字段重填，或者核对 AI 错误花的时间超过直接填写，方案就不成立。不能仅以“输入框少了”或“用了语音”判断成功。

## 2. 先采用的产品原则

1. **一次表达，多处复用。** 用户只描述一次，系统分配到相关字段；同一主诉不在多个阶段重复要求输入。
2. **已知上下文减少选择。** 从客户或排课进入时带入经服务端验证的客户、来源和日期；页首持续显示客户姓名，允许纠正可编辑上下文，身份歧义时仍须选择。
3. **默认看摘要，需要时编辑。** 用中文摘要展示已整理内容，点击某项即可修改；完整表单保留为精确编辑入口，并与摘要共享同一份草稿。
4. **只补缺项，不重走流程。** 依据现有完成规则列出缺失或冲突项，直接跳到对应控件；已经确认的内容不重复询问。
5. **省输入不等于省事实。** 未提及不等于“无”，没测不等于“正常”，旧结果不等于本次结果。AI 不推断临床结论，不自动完成评估。
6. **允许中断与继续。** 草稿保存状态必须真实；失败保留输入并允许重试，完成前明确待补内容。

## 3. 首次评估：一次描述 → 摘要复核 → 补缺项 → 完成

### 3.1 入口与首次录入

从客户详情或首次评估排课进入“记录首次评估”，复用已有首评草稿；已有完成记录时进入查看或复评，不新建第二份首评。

页面提供两个方式：

- **描述本次情况：** 输入一段文字，可使用设备输入法的语音转文字；旁边用简短提示提醒问题、开始时间、影响、目标和实际评估结果，避免让用户记字段名。
- **按项目填写：** 直接进入精简录入区，适合需要准确录入数值、习惯表单或模型不可用的情况。

两种方式编辑同一评估工作草稿，允许随时切换。先支持文字粘贴和设备已有输入方式；产品内置录音与转写另行验证。

### 3.2 摘要与局部修改

整理完成后按“问题与开始情况、生活影响与相关背景、本次评估结果、目标”展示摘要，缺失项显示“尚未记录”。短原文依据可展开查看，数字、侧别、日期与否定表达优先核对。

每项提供“修改”，允许直接改中文文本或类型专用控件。再次补充一句话只更新相关候选：人工已编辑的值优先保留；出现不一致时呈现差异供选择，不覆盖整份草稿。日期默认值须标明来源，“约两周前”保留为开始时间描述，不擅自转成精确发病日期。

客观指标只记录用户明确提供、康复师确认的结果。若只说“膝盖有点痛”，不得补成疼痛 3 分；侧别或场景不明时只问该项，不能借用其他项目的信息。没提供肌力、ROM 或特殊测试时，不自动填正常结果，也不自动增加整套检查。

### 3.3 缺项补充与完成动作

根据当前服务端校验，完成评估需要有效归属、评估日期、主诉、开始日期或描述、康复目标，以及至少一项满足类型规则的客观指标。页面显示“还需补充 2 项”等由真实数据计算的提示，可在同屏补充，长内容再进入相应编辑区域。

现有产品设计另有七类新客户必问内容，覆盖范围大于当前完成校验。**必问内容、必填字段、完成门槛不是同一个概念。** 实施前需要由产品与康复师确认三者关系；本建议不删除七类内容，也不擅自放宽或扩大服务端完成条件。可以降低这些信息的展示负担，但不能把折叠视为已经询问。

未完成时主动作是“保存并稍后继续”；满足条件并复核后提供“完成评估”。整理候选的采用应并入编辑流程，避免用户先确认一遍 AI 候选，再确认保存，再被要求从头填表。最终完成只在康复师主动提交并通过服务端校验后生效；普通草稿保存不需要重复弹框。

按钮与反馈使用准确文案：“草稿已保存，仍需补充开始时间”或“评估已完成”。完成后在原处提供“安排后续课程”等可选下一步，不自动创建计划或排课。

### 3.4 示例

康复师在已绑定客户的页面输入：

> 右膝下楼疼痛，休息会缓解，想恢复正常上下楼。刚才评估右膝下蹲疼痛 3 分。

候选摘要展示主诉、缓解因素、目标和对应疼痛项目；日期若使用当天则显示“预填今天”。对于当前完成条件，继续提示“症状大概什么时候开始？”；七类问诊中尚未记录的背景仍显示待补充，处理方式按确认后的问诊规则执行。

康复师补充“约两周前”，修改或认可候选结果后提交完成。系统保留开始时间描述并进行完成校验。这里展示的是目标交互，当前 AI 评估 schema 与确认服务尚不能承载这条完整流程。

## 4. 不依赖 AI 的低成本改进

| 优化点 | 建议交互 | 边界 |
| --- | --- | --- |
| 主诉重复出现 | 第一处填写，后续显示摘要和“修改”入口 | 共用原字段，不新增第二份主诉 |
| 主观情况输入框过多 | 按“症状影响”“相关背景”分组；扩展输入按用户选择展开 | 必问和需核查内容保持可发现，不因折叠默认已知 |
| 病史、手术与用药内容重叠 | 给各字段清楚职责；一句描述可整理为候选，人工模式也避免重复要求同一事实 | 不将“无既往伤病”推导为“无用药” |
| 添加指标要反复选类型、部位、侧别 | 常用类型提供直接添加；本次同部位项目可点选沿用部位/侧别 | 模板只带项目结构；不带正常结果、旧评分或默认测试结论 |
| 固定五步跳转 | 已知内容摘要展示，缺项直接编辑；五步向导作为辅助方式 | 摘要与表单使用同一草稿，完成仍走同一领域服务 |
| 不完整信息难以中断 | 允许先保存已有信息再继续；分开草稿校验与完成校验 | 当前前端下一步会检查部分必填项，此项需要改动，不能宣称已支持任意中断保存 |
| 保存状态不清楚 | 显示“有未保存内容 / 正在保存 / 已保存 / 保存失败”；提供继续入口 | 不把仅在内存或本地的内容显示为服务端已保存 |

移动端优先使用较大的选项、少量快捷选择和一列编辑区，键盘不遮挡提交与错误提示。常用选项允许补充自由文本，不强迫用户把描述硬塞进预设分类。

## 5. 扩展到其他高频流程

| 场景 | 减少输入的办法 | 不可静默复用的内容 |
| --- | --- | --- |
| 复评 | 优化已有“沿用上次项目”入口；选定后只填本次结果；显示上次日期供比较 | 旧数值、旧阳性/阴性结果、旧疼痛状态 |
| 课后记录 | 从今日排课进入，带入客户和课程日期；支持一句描述与常用动作结构；只核对本次数量、感受与变化 | 上次剂量、上次负荷、上次疗效；“同上次”仍需明确复核本次项目 |
| 课前查看 | 聚合最近已完成评估、上次训练、已确认注意事项，减少多页查找 | 未确认候选、过期限制不能当作当前事实；显示来源与日期 |
| 安排课程 | 在已确定计划或客户的上下文中复用现有批量预览，减少再次选择同一对象 | 不凭一句模糊意向直接生成整批排期；冲突仍需调整 |
| 随访 | 从客户、课程或评估结束处带入上下文，快捷选择时间和目的，允许一句描述 | “下周”对应日期与提醒方式需可见核对；不自动发送外部消息 |
| 新客户建档 | 只先采集当前业务确实需要的信息，其余允许稍后补充；已提供内容不重复问 | 涉及客户唯一识别与归属的信息不能省略；具体最小字段另核对建档约束 |

## 6. 反方验证：最容易失败的地方

- **聊天更费时间。** 如果逐个问题逐轮等待模型，可能比表单慢。优先一次描述、一次缺项清单与局部编辑，支持直接填写，不强制对话轮次。
- **AI 核对成本超过输入成本。** 先验证真实口述中的单位、侧别、否定和不同动作；抽取失败或误改频繁时回到精简表单，而不是要求用户反复重说。
- **历史预填造成错误延续。** 稳定背景也可能变化，需显示来源时间与“沿用/有变化”；临床结果不作为默认本次结果。
- **模板变成新的长表单。** 不按病种自动堆满检查，不默认所有人填写所有项目。先做常用项目快捷入口，再决定是否需要个性化模板。
- **保存减少点击，却增加丢失与并发覆盖。** 自动保存要处理在途请求、失败、离开页面与其他页面修改；服务端恢复到同一草稿，冲突时提示选择。先做好保存状态与恢复，再考虑频繁自动保存。
- **确认按钮的含义不清楚。** “候选已采用”“评估草稿已保存”“评估已完成”需要准确区分；可以减少用户操作层级，但后台校验、事务与审计仍必须完整。
- **语音不是所有环境都适合。** 噪声、客户在场、医学词汇、权限拒绝和错字都会影响录入。先允许设备输入法，再验证内置短录音转写；不默认整场持续录音。

本轮不建议先做全程语音监听、客户端问卷、自动诊断或自动完成评估。这些扩大了依赖与场景，并未证明能解决当前表单负担。

## 7. 实施顺序与依赖

| 优先级 | 范围 | 交付与依赖 |
| --- | --- | --- |
| P0 | 去重、主观信息分组、中文草稿摘要、准确状态文案、直接修改或继续评估入口 | 先解决现有页面成本；优先复用当前字段、草稿和确认接口 |
| P0 | 完成条件与七类问诊的关系核对；现有操作耗时基线 | 确认哪些能折叠、哪些必须显式核查；没有结论不修改完成门槛 |
| P1 | 统一评估工作草稿、一次描述整理、缺项补充、精简表单切换 | 扩展评估候选 schema 与字段依据检查；补齐现有 AI 确认服务不能保存的字段和指标；候选写入仍经评估领域服务 |
| P1 | 草稿保存、恢复与防覆盖；已有首评的继续编辑 | 复用 `AiDraft` 与 `Assessment` 的既有职责：前者承载未采用候选，后者承载评估草稿；确认内容写入当前评估，不另造一套评估表或重复创建首评 |
| P1 | 客观指标快捷录入、复评项目沿用与差异展示 | 保留类型专用规则、历史指标身份和空结果；由真实常用项目决定快捷入口 |
| P2 | 产品内置语音、个人常用模板、其他业务的同类体验优化 | 首评试用有效后再扩展；语音另评估浏览器兼容、识别质量、成本和数据保留方式 |

实现时仍采用“统一交互骨架、按业务校验”，不建立能任意写所有业务表的通用聊天表单。具体 API、草稿并发方案和评估指标候选结构在 P1 细化设计中确认；本建议不直接确定新数据模型。

## 8. 试用与验收

先邀请 3～5 位代表性康复师，用同一组匿名或虚构病例对比当前流程与建议原型。这是发现问题的小规模试用，不作为整体准确率或统计结论。

记录从进入页面到完成有效评估的总用时、主动输入时间、重复输入次数、页面跳转次数、AI 错误修正次数、漏项和中断恢复情况；不能只统计模型速度或输入框数量。可以先提出“总用时中位数下降约 20%”作为试用目标，基线建立后再确认，不作效果承诺。

验收样例至少覆盖：

1. 信息完整的一段描述可生成可编辑摘要，无需重复填写已有主诉。
2. 缺项只提示真实缺失内容；“无、未知、未询问、未测量”不会互相转换；能先保存草稿。
3. 侧别、评分、单位或否定表达有误时，可局部修正；修正后再整理不覆盖人工值。
4. AI 或网络失败时，保留输入，直接填写可继续；不能把失败显示为已保存或已完成。
5. 已有首评草稿从另一入口继续同一份；已有完成首评不创建第二份。
6. 重复提交不会重复写入；只有主动完成且通过服务端校验的评估进入已完成历史、趋势和 AI 事实上下文。
7. 复评沿用项目后，本次数值和分类结果为空，历史结果仅供比较。
8. 手机键盘、切换页面、保存失败和同时编辑时，内容不静默丢失或覆盖。

**采用建议：先落地 P0，再用首评 P1 的小范围试用决定是否扩展。** 如果总用时未下降或错误修正成本上升，优先保留去重后的精简表单，调整抽取和复核方式，不继续堆叠自动化功能。

## 9. P0 实施记录（2026-09-30）

- 主观情况改为主诉摘要与修改入口，复用第一步内容；症状、既往伤病、运动与工作分组。手术、用药和睡眠通过显式展开入口保留，未填写不视为“无”。
- 领域候选卡片采用中文字段名称，可编辑文本、日期和随访类型；确认评估的提示明确为“已存为评估草稿”，提供继续评估入口。候选内修改仅在提交后写入，刷新前未提交编辑不保证恢复。
- 补充按康复师归属读取任意状态草稿的详情接口，已确认和取消的卡片刷新后仍可恢复状态，不重新开放保存操作。
- 修正确认接口统一使用训练校验器导致评估/随访字段被丢弃的问题；现在按数据库草稿类型选择评估、随访或训练校验器，保留人工修改值并拒绝无效日期。
- 评估草稿提供“保存并稍后继续”，不要求先补齐完成条件；字段格式和归属仍须合法。新增保存状态反馈；保存期间禁止编辑，加载失败时禁止误提交并提供重试入口。
