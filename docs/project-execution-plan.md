## 1. 项目目标

V1 目标不是堆叠完整 CRM 功能，而是让单一康复师能稳定完成以下日常闭环：

```text
今日客户 → 课前回顾 → 训练记录 → AI 草稿确认 → 正式保存 → 时间线 → 下次计划
```

V1 成功标准：康复师可以快速找到当天客户；课后用自然语言记录；AI 正确生成可编辑草稿；确认后可追溯保存；下一次课前可看到上次情况和计划。

## 2. 范围与非范围

### V1 范围

- 登录和单康复师数据隔离。
- 客户档案、今日客户和客户时间线。
- 单客户训练记录、训练动作、疼痛、观察与下一步计划。
- AI 训练记录草稿解析与人工确认。
- 审计日志基础能力。

### V1 不做

- 小程序、客户端、多人协作、复杂 Excel 课表解析。
- RAG、异步任务队列、Redis、微服务；LangGraph 不属于 V1 核心闭环，但已列入阶段 6 的受控多分支编排计划。
- 自动推进康复阶段、自动扣课时或 AI 自动修改正式记录。

## 5. 核心验收场景

1. 康复师登录后只能看到自己的客户和记录。
2. 康复师在今日工作台找到客户，进入档案并看到上次训练与下次计划。
3. 康复师创建训练记录，填写动作、训练量、疼痛、观察和计划后正式保存。
4. 康复师输入自然语言训练描述，获得 AI 草稿；编辑并确认后形成正式记录。
5. 未确认、取消或 AI 解析失败时，不产生正式训练记录。
6. 修改已保存训练记录时必须填写原因，且时间线可查到变更历史。
7. 客户列表默认脱敏手机号；无权访问其他康复师的数据。

## 6. 依赖与风险

| 项目 | 风险或依赖 | 应对方式 |
| --- | --- | --- |
| AI 服务商 | API Key、成本、结构化输出稳定性未确定 | 先完成 provider 抽象和 mock；接入前确认服务商与预算 |
| 数据模型 | 评估、课时与课表细则仍存在未决项 | V1 只实现核心训练闭环，未决项进入后续 Backlog |
| 隐私数据 | 健康数据和手机号敏感 | 环境变量、权限隔离、脱敏、审计与测试假数据 |
| Excel 课表 | 格式定制化且尚未提供样本 | 不纳入 V1；拿到真实文件后单独设计 |
| 真实试用 | 需求可能在实际记录过程中调整 | 每阶段验收后安排短试用，反馈进入下一阶段计划 |
