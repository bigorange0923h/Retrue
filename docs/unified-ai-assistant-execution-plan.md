# 统一 AI 助理与任务编排执行计划

> 状态：进行中  
> 适用范围：统一 AI 助理、补记记录、任务恢复、受控 Tool 调用  
> 产品原则：AI 只生成草稿；正式业务数据必须由康复师明确确认后写入。

## 1. 建设目标

将首页、客户详情、课程表、评估页和补充记录入口统一接入同一个 AI 助理。不同入口只负责携带客户、课程、评估等上下文，不再各自维护独立聊天和补记状态。

V1 优先跑通：

```text
进入统一 AI 助理
    → 明确或选择客户
    → 查询相关课程与近期记录
    → 自然语言生成训练补记草稿
    → 康复师编辑并确认
    → 创建正式训练记录
    → 可恢复、可追溯、不重复
```

评估、随访和正式记录修订沿用同一任务基础设施分阶段接入。超长会话自动切换仍只保留设计，不在本次实现范围。

## 2. 已确认的架构决策

采用“统一任务编排，业务内容分域保存”：

```text
Conversation（对话历史）
    └── AssistantTask（统一任务状态）
          ├── AssistantRun（一次 AI 执行）
          ├── ToolExecution（一次受控工具执行）
          ├── TaskEvent（不可变状态事件）
          ├── 子业务草稿
          └── 正式业务结果
```

- `Conversation` 保存消息、摘要和 Episode，不承担补记任务状态。
- `AssistantTask` 统一管理恢复、等待、确认、阻塞、取消和完成。
- `AssistantRun` 单独保存排队、运行、成功、失败和超时，避免一次 AI 失败导致整个任务丢失。
- `ToolExecution` 记录工具名称、执行状态和脱敏摘要；AI 只能建议调用，服务端拥有最终执行权。
- `TaskEvent` 保存状态变化原因，用于恢复、排障和审计。
- 训练、评估、随访分别保存其专业字段，不把全部业务内容塞入统一 JSON。

## 3. 统一任务模型

`AssistantTask` 至少包含：

| 字段组 | 内容 |
| --- | --- |
| 归属 | `therapist_id`、可空 `customer_id`、可空 `conversation_id` |
| 类型 | `skill_code`、`task_type`、`invocation_mode`、`origin` |
| 页面上下文 | `context_resource_type`、`context_resource_id` |
| 恢复 | `status`、`current_step`、`missing_fields`、`state_data`、`version` |
| 关联 | 草稿资源类型/ID、最终结果类型/ID |
| 防重复 | `client_request_id`、`business_key` |
| 时间 | 最近活动、过期、完成、取消、创建和更新时间 |

通用任务状态：

```text
pending → running → waiting_user → waiting_confirmation → completed
                    ↘ blocked
任意未完成状态 → cancelled / expired
不可恢复错误 → failed
```

一次执行状态独立为：`queued`、`running`、`succeeded`、`failed`、`timed_out`、`cancelled`。

## 4. 子业务挂载规则

一个任务只关联一种主要业务草稿：

| 任务类型 | 草稿或业务表 | 正式结果 |
| --- | --- | --- |
| 训练补记 | 现有 `AiDraft`，后续可语义重命名为 `TrainingRecordDraft` | `TrainingRecord` |
| 首次评估/复评 | 现有 `Assessment(status=draft)` | 同一 `Assessment(status=completed)` |
| 随访 | 后续 `FollowUpDraft` 或带严格 schema 的轻量任务草稿 | `FollowUpTask` |
| 训练记录修订 | 修订草稿/差异 | 原 `TrainingRecord` + 审计记录 |

子业务表通过 `assistant_task_id` 关联统一任务。统一任务可保存结果资源类型和 ID 供统一列表跳转，但正式业务校验仍由各自 service 完成。

## 5. 任务恢复机制

恢复不得依赖浏览器缓存，也不得重新让 AI 阅读整段聊天猜测进度。服务端在每个关键步骤保存结构化检查点：

1. 普通咨询先保存为 Conversation 消息；只有进入业务流程时才创建任务和执行记录。
2. 客户、课程、日期、已收集字段和缺失字段随步骤更新。
3. 草稿生成后保存草稿 ID，并进入 `waiting_confirmation`。
4. 页面重开时查询当前康复师的可恢复任务。
5. 正式确认前重新校验客户、课程、评估和原记录状态。
6. 数据已变化时进入 `blocked`，展示康复师可执行的处理建议。
7. 运行超过 AI 超时加缓冲仍未结束时，服务端在查询任务时将其标记为可重试失败；不会永久卡在“处理中”。

用户界面统一显示“待你确认”和“最近聊过”。从客户或课程进入时优先展示该资源的未完成任务；不得把一个客户的任务静默切换给另一个客户。

## 6. 幂等与并发

- 训练解析和正式确认使用客户端唯一请求号，页面超时后先查询原执行状态。
- 创建任务对 `client_request_id` 幂等。
- 同一康复师、同一非空 `business_key` 的未完成任务优先复用。
- 草稿确认在事务中锁定草稿并复查状态。
- 同一任务重新解析会作废上一份待确认草稿；同一时刻只允许一个解析执行。
- 正式确认使用 `idempotency_key`；重复确认返回第一次创建的正式记录。
- 非空课程关联只能对应一条正式训练记录。
- 任务使用 `version` 支持多页面并发更新检测。

建议业务键示例：

```text
training:course_session:123
initial_assessment:customer:456
revision:training_record:789
```

## 7. Tool 分层与安全规则

### 只读 Tool

- 搜索当前康复师名下客户。
- 查询客户上下文、首次评估状态和近期记录。
- 查询客户课程及单节课程状态。
- 查询随访和风险提示。

### 草稿 Tool

- 生成或更新训练补记草稿。
- 生成评估建议填入草稿。
- 生成随访草稿。

### 确认 Tool

- 确认训练补记并创建正式记录。
- 完成评估或创建随访时再次调用领域 service。
- 修订正式记录必须包含原因并展示前后差异。

安全约束：

- `therapist_id` 只能来自登录身份，禁止由 AI 或客户端指定。
- `context_resource_type` 使用白名单，并校验资源、客户和康复师一致。
- AI、记忆、业务备注和 Tool 返回均视为不可信输入，必须通过 schema 和权限校验。
- 写 Tool 永不由 AI 自动确认；康复师确认是独立操作。
- 限制单轮 Tool 数量、输入长度和重试次数，避免循环调用和成本失控。
- Tool 日志只保存脱敏摘要，不保存完整手机号、病史或提示词。

## 8. 记忆和正式事实边界

上下文优先级：

```text
当前正式业务数据
    > 康复师确认的长期记忆
    > 康复师确认的 Episode
    > 康复师本轮原话
    > AI 推测和未确认草稿
```

- AI 回复、未确认草稿和 Tool 原始结果不得形成长期记忆。
- 正式训练和评估通过业务查询读取，不复制成第二份长期事实。
- 对话摘要不能替代任务状态或正式记录。
- 冲突记忆不得自动覆盖；条件并存必须记录具体适用条件和独立记忆键。
- 任务恢复只读取任务、运行和草稿数据，不依赖滚动摘要。

## 9. 统一页面与入口

| 入口 | 默认模式 | 携带上下文 |
| --- | --- | --- |
| 全局“跟 AI 说一段” | 智能识别 | 当前页面 |
| 全局“按客户补记” | 引导式补记 | 待选择客户和记录类型 |
| 客户详情 | 客户讨论 | 客户 ID |
| 课程表/课程详情 | 训练补记 | 客户、课程、日期 |
| 评估页面 | 评估主题 | 客户、评估 ID |
| PC AI 入口 | 普通助手 | 当前页面上下文 |

页面只使用康复师能理解的文案，不展示 Agent、Skill、Tool、Run 等内部术语。移动端采用单列布局，输入、草稿卡片和操作按钮占满可用宽度。

“智能识别”采用保守策略：普通咨询中只有出现明确补记指令，或同时出现训练时间、训练量、观察反馈、下次计划等多类信号时，才询问康复师是否切换到训练补记；选择“按咨询发送”仍保留为普通对话，绝不自动创建正式记录。

## 11. 验收标准

- 康复师从任一入口进入同一个 AI 助理，并能明确看到当前客户和主题。
- 退出页面后，收集中、处理中和待确认任务均能准确恢复。
- 页面超时、重复点击和多窗口操作不会产生重复正式记录。
- 任何读取和写入都不能跨康复师、跨客户或错误关联课程。
- AI 未经确认不创建或修改正式训练、评估、课程、阶段和随访数据。
- 草稿、AI 回复和 Tool 返回不会污染长期记忆。
- 正式确认、取消、失败和重试均有可追踪事件。
- PC 与移动端构建通过；后端迁移、检查和权限/幂等测试通过。

## 12. 暂不纳入本次自动化范围

- 超长会话自动结束和切换 Conversation。
- 多客户批量一次性正式写入。
- AI 自动完成评估、修改康复阶段或修改历史正式记录。
- 未经康复师确认自动处理记忆冲突或风险提示。
