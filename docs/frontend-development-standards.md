# Retrue 前端开发规范

## 1. 通用原则

- V1 优先实现「今日客户 → 训练记录 → AI 草稿确认 → 客户时间线 → 下次备课」业务闭环，避免提前引入复杂架构。
- 保持组件与模块职责单一；优先复用已有组件、组合式函数和类型，避免复制业务规则。
- 每次修改应保持前后端类型、接口字段同步，并运行相关校验或构建。

## 2. 目录与职责

- 页面放在 `src/views/`；可复用业务组件放在 `src/components/`；通用组件放在 `src/components/common/`。
- API 调用集中在 `src/api/`；Pinia 状态集中在 `src/stores/`；共享 TypeScript 类型放在 `src/types/`。
- 页面不得直接散落 Axios 请求；通过 API 模块调用，并使用统一响应类型。
- 同一业务字段、状态和值域必须复用类型和常量，不在多个组件中重复定义。

## 3. 组件、类型与注释

- Vue 组件文件使用 `PascalCase.vue`；组合式函数使用 `useXxx.ts`；变量和函数使用 `camelCase`。
- 每个组件、组合式函数、API 模块的职责应清晰；复杂交互、业务判断与数据转换必须添加中文注释。
- Props、emit、接口响应和表单模型均须定义 TypeScript 类型，禁止无必要的 `any`。
- 组件只负责展示和交互；跨页面业务状态放入 Pinia，复杂业务计算放在 composable 或 service 层。

## 4. API 调用

- 所有业务接口按后端规范解析统一响应：`{ code, message, data }`。
- `code === 200` 才视为成功；其他业务码统一提示 `message`，不得假设 HTTP 200 即业务成功。
- 请求、响应和分页结构必须声明 TypeScript 类型；需要时通过 Axios 拦截器集中处理认证与错误。
- 不在前端保存 AI Key、数据库密码、完整敏感客户信息或后端内部错误详情。

## 5. 视觉主题与设计系统

### 5.1 设计定位

- 视觉定位为专业、轻量、健康、可信，带有克制的 AI 感；不做传统 ERP/CRM 式密集后台。
- 页面使用白色内容表面与浅灰背景分区，保留充足留白、轻微阴影和大圆角。
- PC 主框架采用左侧导航 + 右侧工作区；移动端后续采用任务式导航，不直接压缩 PC 布局。
- 避免大面积复杂渐变、过度装饰、重阴影和无业务价值的图表。仅品牌标识或登录页背景可使用克制的浅色渐变。

### 5.1.1 响应式规则

- 以 `768px` 为手机端断点；桌面布局不得仅依赖浏览器缩放来适配手机。
- 同一路由使用 `useViewport()` 判定视口，并通过 `AdaptiveXxxView` 分别渲染 `DesktopXxxView` 与 `MobileXxxView`；禁止以 User-Agent 作为页面选择依据。
- 手机端使用固定底部高频导航：今日工作台、客户管理、课程管理、快速记录；低频配置功能不占用底部导航。
- 手机端内容区保留底部导航安全距离，页面左右留白为 `12px`，顶部工作区留白为 `16px`。
- 工具栏、页头、操作区在窄屏必须可换行；搜索和筛选控件应占满可用宽度。
- 行内多字段表单在手机端改为一至两列网格；输入、选择、日期控件不可溢出视口。
- 数据表允许横向滚动，不得通过缩小到不可读字体来强行容纳所有列；日历单元格在手机端降低高度。
- 弹窗在手机端宽度为 `calc(100vw - 32px)`，表单标签改为顶部显示，操作按钮保持可点击尺寸。

### 5.2 主题令牌

全局视觉令牌定义在 `src/style.css`，新增页面或组件必须优先使用令牌，不得重复定义同类颜色、圆角、阴影或字体。

| 用途 | 令牌 | 当前值 |
| --- | --- | --- |
| 主操作与选中状态 | `--retrue-primary` | `#07A358` |
| 主色深色态 | `--retrue-primary-dark` | `#06874A` |
| 主色浅背景 | `--retrue-primary-light` | `#E6F7EF` |
| AI 状态 | `--retrue-ai` | `#7C3AED` |
| 风险状态 | `--retrue-risk` | `#D4380D` |
| 回访 / 待处理 | `--retrue-visit` | `#F59E0B` |
| 信息 / 评估 | `--retrue-assess` | `#2563EB` |
| 页面背景 | `--retrue-bg` | `#F5F6F5` |
| 卡片表面 / 覆盖表面 | `--retrue-surface`、`--retrue-surface-overlay` | 见全局样式 |
| 边框 | `--retrue-border` | `#E8E8E8` |
| 正文 / 次级 / 弱化文本 | `--retrue-text`、`--retrue-text-secondary`、`--retrue-text-muted` | 见全局样式 |
| 圆角 | `--retrue-radius-lg/md/sm` | `16px / 10px / 8px` |
| 阴影 | `--retrue-shadow`、`--retrue-shadow-hover`、`--retrue-shadow-top` | 见全局样式 |

- 字体顺序统一使用 `PingFang SC`、`Microsoft YaHei`、`Helvetica Neue` 和系统字体回退。
- 禁止在业务组件中直接写新的十六进制颜色、阴影、圆角或字体；确有新语义时，先在 `src/style.css` 增加带 `--retrue-` 前缀的全局令牌。
- 白色文字等无替代的极少数例外应附中文注释说明用途。
- 禁止使用内联 `style`、页面级魔法数颜色、局部渐变或复制 Element Plus 的默认视觉参数；间距、布局等局部结构样式除外。

### 5.3 Element Plus 与通用样式

- Element Plus 主色必须继承 `src/style.css` 中的 `--el-color-primary` 覆盖，不在单个页面覆盖 Element Plus 全局变量。
- 卡片优先使用 `.retrue-card` 或同等的 token 组合：白色表面、`--retrue-radius-lg`、`--retrue-border` 和 `--retrue-shadow`。
- 页面主容器使用 `.retrue-page`，最大宽度 `1200px`；桌面端内容区域默认使用 `24px 28px` 的留白。
- 状态色仅用于相应语义：紫色仅 AI，橙色仅回访/待处理，红色仅风险，蓝色仅信息/评估；不得作为任意装饰色。

### 5.4 UI 元素准入规则

- 所有交互控件必须优先使用 Element Plus 或项目内已封装的业务组件：按钮、输入框、选择器、日期选择、弹窗、抽屉、上传、标签、表格和分页均不得自行用原生控件重造。
- 禁止新增原生 `button`、`input`、`select`、`textarea`、`table`、`dialog` 等交互 UI；语义容器如 `main`、`section`、`div`、`span`、标题和段落可正常使用。
- 新增 UI 必须先确认是否已有 Element Plus 组件、现有业务组件或设计 token 可复用；没有明确业务需求和设计依据时，不得添加装饰图标、色块、渐变、悬浮按钮、统计图或其他视觉元素。
- 新业务组件应先定义职责、状态与视觉语义，再实现；跨页面复用的样式或组件必须沉淀到全局设计系统或 `src/components/common/`。
- 评审时检查：是否复用 token、是否复用组件、是否存在原生交互控件、是否新增了设计文档未定义的视觉元素。

## 6. UI 与交互

- Element Plus 仅作为基础控件，业务场景优先封装业务组件，不直接堆砌默认表格和表单。
- 所有 AI 输出必须明确标记为“草稿 / 待确认”，提供编辑、确认与取消入口。
- 处理加载、空数据、失败和无权限状态；破坏性操作必须二次确认。
- 中文用户文案应简洁明确；用户可见的错误信息不得含技术栈或敏感详情。

## 7. 验证与提交

- 每次前端改动至少执行 `npm run build`；新增复杂逻辑时补充组件或工具函数测试。
- 不提交 `node_modules`、`dist`、`.env` 或真实客户数据。
- 每个提交聚焦单一目的；接口变更需同步更新前端类型和相关页面。
